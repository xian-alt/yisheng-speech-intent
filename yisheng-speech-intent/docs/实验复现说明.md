# 实验复现说明

## 数据和评估协议

流程为：录音 → Qwen3-ASR转写 → 参与者校对 → 三种分类方法 → 对照固定参考标签 → 计算总体、逐类和SOS指标。

- `data/training/dataset.json`：371条训练文本、75条开发文本，沿用保存的split，不重新划分。
- `data/training/prompt.txt`：基础语言模型和LoRA共用的中文七类提示词。
- `data/evaluation.sqlite3`：700条录音对应的匿名ASR/校对文本、参考标签及14组历史预测，共9800条预测。
- `results/svm/predictions.jsonl`：新增SVM的1400条预测，按匿名录音编号连接SQLite参考标签。

录音来自两位参与者，每人350条、每人每类50条；12条转写经校正。ASR与校对条件使用相同录音编号和参考标签。录音未用于梯度训练，但曾用于开发阶段错误分析。因此，所列成绩属于同批录音上的开发阶段回归评估，而非新采集独立留出测试。

## 从归档预测复算

在程序目录运行，无需模型权重：

```powershell
python reproduce_metrics.py > metrics-llm.json
python scripts/reproduce_svm_metrics.py > metrics-svm.json
```

两条命令均将逐条预测与参考标签比较，并核对保存的指标。`reproduce_metrics.py`保留14组历史结果；当前论文语言模型比较取compact_regression的base和v21。

计分使用固定七类Macro Precision、Recall和F1，零分母按0处理。非法或失败输出保留为 `__FAILED__` 并计错，不从700条分母中移除。SOS漏报率为FN/100，误报率为FP/600。

## TF-IDF + Linear SVM

```powershell
python -m pip install -r requirements-svm.txt
python -m unittest discover -s tests -v
python scripts/svm_baseline.py train --source . --data data/training/dataset.json --output runs/svm-train
python scripts/svm_baseline.py evaluate --source . --database data/evaluation.sqlite3 --frozen runs/svm-train --output runs/svm-evaluation
python scripts/svm_baseline.py benchmark --source . --data data/training/dataset.json --frozen runs/svm-train --output runs/svm-resources
```

特征为字符1–3 gram TF-IDF，词表和IDF只在371条训练文本拟合。LinearSVC使用L2正则、squared-hinge损失和one-vs-rest，固定种子20261025。仅在75条开发文本比较C={0.1,1,10}，按七类Macro F1选择，同分取较小C；最终C=1，特征数6599。开发文本不并回训练。

SVM脚本分开执行train和evaluate。模型、数据和脚本哈希存入frozen.json；评估阶段加载固定模型，不重新拟合或选择参数。文件位置如下：

| 文件 | 内容 |
|---|---|
| `scripts/svm_baseline.py` | CPU训练、固定模型评估、资源测量 |
| `scripts/reproduce_svm_metrics.py` | 标准库复算已保存SVM指标 |
| `configs/svm_baseline.json` | 原运行参数、开发候选成绩、依赖版本、数据/模型哈希 |
| `results/svm/predictions.jsonl` | condition、utterance_id、score_label三列的预测导出 |
| `results/svm/metrics.json` | 两条件总体、逐类、分说话人和SOS指标 |
| `results/svm/resources.json` | CPU耗时、模型文件字节和进程内存记录 |
| `results/svm/latencies.csv` | 7500次调用的延迟明细 |

ASR条件正确658/700，Accuracy=94.00%、Macro F1=94.02%；校对条件正确659/700，Accuracy=94.14%、Macro F1=94.16%。两条件SOS均为TP=100、FP=1、FN=0、TN=599。

资源测量使用i7-13700HX CPU，batch=1、线程上限4。预热20次后，对75条开发文本完整遍历100轮，共7500次调用；中位数0.37ms、P95为0.57ms。计时包括TF-IDF转换和分类，不包括ASR、加载模型或磁盘读取。完整Pipeline文件207648字节，约203KiB。峰值工作集约147.50MiB，统计对象是包含解释器和依赖的整个Python进程，不是模型单独内存。硬件与负载变化会影响耗时。

## 重新运行基础模型与LoRA

准备本地Qwen2.5-0.5B-Instruct及论文LoRA适配器，安装 `requirements.txt`。记录环境为PyTorch 2.7.0+cu128、Transformers 4.57.6、PEFT 0.18.1；语言模型比较使用GPU float16。

```powershell
$base = "D:/models/Qwen2.5-0.5B-Instruct"
$adapter = "D:/models/care-intent-adapter"
New-Item -ItemType Directory -Force runs | Out-Null
python reproduce_metrics.py --export-inputs runs/paper-inputs.json > runs/archive-metrics.json
python scripts/intent_v2_research.py evaluate --data data/training --output runs/paper-evaluation --base "$base" --v1 "$adapter" --v2 "$adapter" --references runs/paper-inputs.json --prompt-file data/training/prompt.txt --device cuda:0 --methods "base,v2"
```

`--v1`是旧脚本的必填兼容参数；这里与 `--v2` 指向同一当前适配器，实际只运行 `--methods "base,v2"` 指定的方法。不要省略methods参数；原脚本的simple方法是逻辑回归，与本次Linear SVM不同。

两种语言模型使用相同提示词和七类输出规则、贪心解码、最多16个新token、转写截取前500字符。相同方法和配置下的相同输入可缓存复用，全部录音仍逐条计分。新运行输出base_predictions.jsonl、v2_predictions.jsonl、metrics.json和evaluation_config.json。

## LoRA训练与单条音频

```powershell
python scripts/intent_v2_research.py train --data data/training --output runs/care-lora --base "$base"
```

训练使用371/75划分，5个epoch，batch=2，梯度累积4，学习率0.0002，最大长度1024；LoRA rank=8、alpha=16、dropout=0.05，作用于q/k/v/o及gate/up/down投影。仅助手标签和结束token计算loss，每个epoch评估开发集并选择loss最低的检查点。完整记录见 `configs/train_v21.json`；新训练权重及成绩另行保存。

单条音频或文本识别使用 `recognize.py`：

```powershell
python recognize.py --base "$base" --adapter "$adapter" --text "请给我倒杯水" --device cuda:0
python recognize.py --base "$base" --adapter "$adapter" --audio "D:/audio/utt-0001.mp4" --asr-model "D:/models/Qwen3-ASR-1.7B" --device cuda:0
```

音频识别另需 `requirements-asr.txt` 和本地Qwen3-ASR-1.7B。原ASR文本与参与者校对文本保持分开；重新转写或修订参考标签后，需要重新计算对应指标。数据库结构见 `data/schema.sql`。


## 语言模型资源与固定检查点重复推理

本轮补充与论文第41版表4对应，原分类分数和参考标签不变。文件位于`results/llm_resources/`。基础模型与LoRA的两种文本条件预测均与原SQLite归档逐条一致。

RTX 5060 Laptop GPU、batch=1、基础权重float16、LoRA适配器未合并；每种方法在独立Python进程中运行。预热20次后，对700条ASR文本逐条无缓存分类。基础模型延迟中位数/P95为142.34/263.12 ms，LoRA为181.96/312.80 ms。计时包含分词、模型生成、解码与解析，排除ASR、模型加载和写盘。两种文本条件评估阶段的峰值CUDA allocated显存分别为0.956和0.976 GiB，包含模型权重。

另对相同75条开发文本重复推理三轮，共225次调用，不使用缓存。两模型各自三轮预测均一致；三轮平均延迟的均值与样本标准差分别为168.32 ± 22.95 ms和229.64 ± 11.48 ms。这里的重复统计不代表独立训练种子之间的波动；本轮没有全量微调比较。

```powershell
python scripts/reproduce_llm_resources.py
```

该命令仅用标准库核对归档预测、计时统计、数据与提示词哈希。完整文件清单、统计边界及显存记录的解释见[LLM资源说明](../results/llm_resources/README.md)。
