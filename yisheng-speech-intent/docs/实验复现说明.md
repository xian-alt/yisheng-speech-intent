# 论文实验怎么运行

本文档对应目前论文的四张表，只使用仓库中已有的入口，没有新增测试程序。先说明实验如何得到结果，再列出实际运行命令。

## 一、从录音到四张表

流程为：录音 → Qwen3-ASR转写 → 保存原始文本 → 参与者校对文本 → 两种文本分别送入基础模型和LoRA模型 → 校验输出标签 → 与固定参考标签比较 → 计算四张表。

700条录音来自两位参与者，每人350条、每人每类50条，共七类、每类100条。原始ASR文本与校对文本对应同一条录音；12条录音的转写文本经校正。参考意图保存在数据库的`reference_label`字段中。模型推理时不接收这个参考标签，只接收任务提示词和待分类文本；参考标签只在评分时使用。

七个输出标签为`REQUEST_WATER`、`REQUEST_FOOD`、`REQUEST_TOILET`、`CALL_CAREGIVER`、`MEDICINE_REMINDER`、`SOS`和`UNKNOWN`。任务是识别当前仍然有效的主要请求。模型需要区别当前请求、否定、改口和过去事件，而不是只查找句子中的关键词。

### 四张表与数据的对应关系

| 论文位置 | 输入 | 方法 | 数据库中的分组 |
|---|---|---|---|
| 表1 | 原始ASR文本 | 基础模型、LoRA模型 | `compact_regression/base/asr`、`compact_regression/v21/asr` |
| 表2 | 参与者校对文本 | 基础模型、LoRA模型 | `compact_regression/base/proofread`、`compact_regression/v21/proofread` |
| 表3 | 原始ASR文本 | LoRA模型逐类结果 | `compact_regression/v21/asr`中的`per_class` |
| 表4 | ASR或校对文本 | 基础模型ASR、LoRA模型ASR、LoRA模型校对文本 | 对应分组中的`sos` |

`compact_regression`和`v21`是归档时保存的键名。论文中的“the LoRA model”对应这里的`v21`；不要改动数据库键名，也不要把文件名中的版本号当成另外一个模型结果。

数据库保留了14组历史比较，共9800条预测。当前论文只使用上表中的四组，共2800条预测；它们仍然来自同一批700条录音。表3和表4是这些预测的进一步统计，不是另外收集的数据。

## 二、代码在哪里

本说明位于代码目录的`docs/`下。下表路径均从代码目录计算。

| 文件 | 实际作用 |
|---|---|
| `yisheng/qwen_asr.py` | `QwenASRAdapter.transcribe()`加载Qwen3-ASR并返回文本 |
| `recognize.py` | 已有的单条音频或单条文本识别入口 |
| `yisheng/models.py` | `QwenIntentAdapter`加载基础模型和可选LoRA适配器，拼接提示词、生成并解析输出 |
| `yisheng/intents.py` | 标签、别名及输出格式解析；批量评测还会限制为论文七类 |
| `data/training/prompt.txt` | 实际训练、推理共同使用的中文提示词 |
| `data/training/dataset.json` | 已冻结的371条训练样本和75条开发样本 |
| `scripts/intent_v2_research.py` | 现有研究脚本；`train()`负责训练，`evaluate()`负责批量推理，`score()`负责新推理结果评分 |
| `reproduce_metrics.py` | 读取已归档预测，不运行模型，重新计算并核对指标 |
| `data/evaluation.sqlite3` | 700条转写、参考标签和已保存的逐条模型预测 |
| `tests/test_reproduction.py` | 数据库完整性及非法输出计错规则检查 |
| `configs/train_v21.json` | 实际训练配置 |
| `configs/protocols.json` | 实验分组、提示词哈希、模型哈希和推理设置 |
| `configs/recorded_versions.json` | 归档的软件版本 |
| `metadata/source_manifest.json` | 源文件及公开导出文件的SHA-256记录 |

## 三、准备运行目录

克隆仓库后，进入包含`recognize.py`和`reproduce_metrics.py`的子目录：

```powershell
git clone https://github.com/xian-alt/yisheng-speech-intent.git
cd yisheng-speech-intent
cd yisheng-speech-intent
```

仓库名与代码子目录同名，所以这里连续进入两层。下面的命令都在代码子目录运行。

只核对已保存的论文成绩，需要Python标准库，不需要GPU或模型权重。模型训练及重新推理另需安装相关依赖，并准备本地模型。论文推理使用GPU float16，训练配置见后文；CPU演示不能据此复现GPU耗时。

## 四、先复算已保存的论文成绩

```powershell
python reproduce_metrics.py > metrics-all.json
python -m unittest discover -s tests -v
```

第一个命令读取SQLite，重新计算全部14组归档指标，并与归档参考值比较；发生不一致时会报错。第二个命令运行现有检查，不会启动模型。

Windows PowerShell中可以查看当前论文的四组结果：

```powershell
$m = Get-Content -Raw -Encoding UTF8 metrics-all.json | ConvertFrom-Json
$m.'compact_regression/base/asr'
$m.'compact_regression/v21/asr'
$m.'compact_regression/base/proofread'
$m.'compact_regression/v21/proofread'
```

查看表3和表4对应内容：

```powershell
$m.'compact_regression/v21/asr'.per_class | ConvertTo-Json -Depth 5
$m.'compact_regression/base/asr'.sos
$m.'compact_regression/v21/asr'.sos
$m.'compact_regression/v21/proofread'.sos
```

输出中的比例乘以100再保留两位小数，就是论文百分数。应从未四舍五入的逐类数值计算宏平均，不应先截断各类结果。

这一步是“从预测记录复算成绩”。它证明公开记录能够产生论文中的分数，不代表重新运行了ASR或语言模型。

## 五、重新运行基础模型与LoRA模型的测试

### 1. 模型和依赖

需准备本地Qwen2.5-0.5B-Instruct，以及用于论文结果的LoRA适配器目录。仓库目前没有发布基础模型或LoRA权重；仅下载代码，能够复算分数，但还不能直接重新运行该适配器的推理。可以向仓库维护者取得对应权重，或按第六节重新训练；新训练的权重和成绩需要另行保存，不能直接当作原论文权重。

安装记录在仓库中的推理、训练依赖：

```powershell
python -m pip install -r requirements.txt
```

PyTorch需要与本机GPU驱动匹配的CUDA构建。归档环境为PyTorch 2.7.0+cu128、Transformers 4.57.6、PEFT 0.18.1；其他记录见`configs/recorded_versions.json`。本次文档整理没有重新安装这些依赖或重跑GPU测试。

设置本地路径，以下路径是示例，应替换为实际目录：

```powershell
$base = "D:/models/Qwen2.5-0.5B-Instruct"
$adapter = "D:/models/care-intent-adapter"
```

原论文适配器的`adapter_model.safetensors`应具有以下SHA-256：

```text
4b0ca128a047a0ac71025b22cc891851276cf8f4366de8e4f786cb33605e8136
```

可以本地检查：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "$adapter/adapter_model.safetensors"
```

### 2. 从数据库导出同一批700条输入

```powershell
New-Item -ItemType Directory -Force runs | Out-Null
python reproduce_metrics.py --export-inputs runs/paper-inputs.json > runs/archive-metrics.json
```

先创建`runs/`目录，使输出重定向也能正常写入。`paper-inputs.json`包含录音匿名编号、两种转写文本和评分用参考标签，不改变数据库。导出文件不能已存在；重复运行时请使用新文件名。

### 3. 使用现有研究脚本推理

```powershell
python scripts/intent_v2_research.py evaluate --data data/training --output runs/paper-evaluation --base "$base" --v1 "$adapter" --v2 "$adapter" --references runs/paper-inputs.json --prompt-file data/training/prompt.txt --device cuda:0 --methods "base,v2"
```

**为什么命令仍有`--v1`：**这是原脚本的必填兼容参数，脚本会无条件读取该目录中的适配器哈希。为保持代码原样，这里将它指向同一个当前适配器。真正运行哪些模型由`--methods "base,v2"`决定：只运行未加载适配器的基础模型和加载当前适配器的LoRA模型，不运行第三个模型或传统文本分类器。新生成配置中的`v1`槽位因此是兼容占位，不是历史适配器的真实身份；不要把该槽位当作额外实验。

必须保留`--methods "base,v2"`。脚本默认还包含其他历史方法，直接省略这个参数会运行不同范围的实验。`--output`目录不能已经存在。

测试输入包含75条合成开发样本、700条原始ASR文本及700条校对文本。当前论文表格只取后两组，每组700条，不将75条开发样本加入测试分母。

两种语言模型共用提示词和七类标签；贪心解码，最多生成16个token，输入转写截取前500个字符。随机种子为20261025，CPU线程数为4；本命令推理精度为GPU float16。程序缓存同一模型、同一配置下完全相同的文本，复用情况记录在`cache_reused`字段，全部录音仍逐条计分。

### 4. 运行后得到什么

| 输出文件 | 内容 |
|---|---|
| `runs/paper-evaluation/base_predictions.jsonl` | 基础模型的逐条文本、参考标签、原始回答、解析结果和计分标签 |
| `runs/paper-evaluation/v2_predictions.jsonl` | LoRA模型对应的逐条记录 |
| `runs/paper-evaluation/metrics.json` | 各输入条件的总体指标、逐类结果、混淆计数和SOS指标 |
| `runs/paper-evaluation/evaluation_config.json` | 本次模型路径、哈希、提示词、数据集、设备、精度和解码设置 |

这里新推理结果使用`base`、`v2`作为方法键，条件键为`regression700_asr`和`regression700_proofread`；归档数据库则使用`base`、`v21`及`asr`、`proofread`。它们是同一当前论文方法与条件的不同存储名称。

`metrics.json`中，表1读取`base/regression700_asr`与`v2/regression700_asr`；表2读取两者的`regression700_proofread`；表3读取`v2/regression700_asr/per_class`；表4读取相应条件的`sos`。不要用`synthetic_dev`替换论文测试成绩。

## 六、LoRA是怎么训练的

这一节使用已有训练子命令。若只复算已保存的论文分数，不需要重新训练。

```powershell
python scripts/intent_v2_research.py train --data data/training --output runs/care-lora --base "$base"
```

输出目录不能已存在；`$base`按第五节设置。训练需要CUDA GPU。基础模型参数冻结，只更新LoRA参数；训练文本没有换成这700条测试录音。

| 项目 | 实际设置 |
|---|---|
| 训练集 / 开发集 | 371 / 75条合成文本—标签样本 |
| 共同提示词 | `data/training/prompt.txt` |
| LoRA目标层 | q、k、v、o及gate、up、down投影 |
| rank / alpha / dropout | 8 / 16 / 0.05 |
| epochs | 5 |
| 每设备batch size / 梯度累积 | 2 / 4 |
| 学习率 | 0.0002 |
| 最大序列长度 | 1024 tokens |
| 随机种子 | 20261025 |
| 损失范围 | 仅助手标签与结束token；提示词和padding不计损失 |
| 选取检查点 | 每个epoch评价合成开发集，选择开发损失最低者 |

训练支持时使用bfloat16，否则回退float16；最终选择与实际精度会记录在新运行目录。输出包括`adapter/`、`training_config.json`、`trainer_state.json`、`events.jsonl`及`training_results.json`。训练后的`adapter/`可交给第五节的已有测试命令，但新训练模型的分数需要实际测量，不能直接填入原论文成绩。

371条中包含275条新编写合成样本和96条去重后的历史合成样本；75条开发样本为另行编写的合成文本。它们与用于比较ASR和校对条件的700条录音分开统计。原始文件及哈希保留在仓库，不重新划分训练/开发集。

## 七、音频怎么转写、怎么做单条识别

已有ASR代码位于`yisheng/qwen_asr.py`。它使用本地Qwen3-ASR-1.7B，固定中文、批大小1、最大生成长度256个token；GPU使用float16，CPU使用float32。

若要处理音频，安装可选依赖并准备本地ASR模型：

```powershell
python -m pip install -r requirements-asr.txt
```

`requirements-asr.txt`中的`qwen-asr`没有锁定版本。重新安装时需记录实际版本；为避免改变已有分类环境，可以另建ASR环境。本次整理未把未锁定的ASR依赖声称为完全相同的原始环境。

调用已有单条音频入口：

```powershell
python recognize.py --base "$base" --adapter "$adapter" --audio "D:/audio/utt-0001.mp4" --asr-model "D:/models/Qwen3-ASR-1.7B" --device cuda:0
```

也可以只给转写文本，检查模型回答：

```powershell
python recognize.py --base "$base" --adapter "$adapter" --text "请给我倒杯水" --device cuda:0
```

单条识别输出包括`transcript`、`raw_output`、`parsed_result`、`valid`和`score_label`。去掉`--adapter`即使用基础模型。

现有公开代码提供单条音频识别入口和批量文本评测入口，没有独立的700条音频批量转写入口。本次按维护者要求只整理现有代码，没有另外新增入口。论文指标以数据库中已冻结的ASR文本为准；重新对音频执行ASR可能产生不同文本，应保存为新结果，不能覆盖原始转写后仍沿用旧成绩。

参与者校对属于人工步骤，不能由脚本“自动生成校对文本”。如果复现者重新录音、重新校对或更改参考标签，需要重新计算对应分数，并与归档结果分开报告。

## 八、评分规则和应得到的数字

总体准确率是正确分类数除以700。Precision、Recall、F1先对七类分别计算，再取七类宏平均；分母为零的项按零处理。非法响应或异常对应`__FAILED__`，仍计入700条分母并按错误处理，不改判成正确的UNKNOWN。

| 输入 | 方法 | 正确数 | Accuracy | Macro P | Macro R | Macro F1 |
|---|---|---:|---:|---:|---:|---:|
| ASR | 基础模型 | 342/700 | 48.86% | 53.93% | 48.86% | 45.70% |
| ASR | LoRA模型 | 689/700 | 98.43% | 98.58% | 98.43% | 98.50% |
| 校对文本 | 基础模型 | 341/700 | 48.71% | 54.70% | 48.71% | 45.63% |
| 校对文本 | LoRA模型 | 693/700 | 99.00% | 99.15% | 99.00% | 99.07% |

表3对应LoRA的ASR条件：

| 标签 | Precision | Recall | F1 | 数量 |
|---|---:|---:|---:|---:|
| REQUEST_WATER | 99.01% | 100.00% | 99.50% | 100 |
| REQUEST_FOOD | 98.04% | 100.00% | 99.01% | 100 |
| REQUEST_TOILET | 100.00% | 98.00% | 98.99% | 100 |
| CALL_CAREGIVER | 97.98% | 97.00% | 97.49% | 100 |
| MEDICINE_REMINDER | 100.00% | 98.00% | 98.99% | 100 |
| SOS | 99.01% | 100.00% | 99.50% | 100 |
| UNKNOWN | 96.00% | 96.00% | 96.00% | 100 |

SOS作为正类，其余六类作为负类。漏报率为`FN/(TP+FN)`，分母100；误报率为`FP/(FP+TN)`，分母600。

| 表4的方法与输入 | TP | FP | FN | TN | 漏报率 | 误报率 |
|---|---:|---:|---:|---:|---:|---:|
| 基础模型，ASR | 98 | 92 | 2 | 508 | 2.00% | 15.33% |
| LoRA模型，ASR | 100 | 1 | 0 | 599 | 0.00% | 0.17% |
| LoRA模型，校对文本 | 100 | 0 | 0 | 600 | 0.00% | 0.00% |

ASR条件下SOS的Precision为100/101=99.01%，Recall为100/100=100%，因此表3和表4可以相互核对。LoRA的ASR总错误数11，校对条件错误数7；两种条件各保留一条非法响应并按错误计分。

## 九、目前能复现到什么程度

- 无模型、无GPU：可从SQLite复算全部归档分数，核对当前论文四张表。
- 有基础模型和原论文适配器：可使用现有批量脚本重新运行四组文本比较。必须保留原始提示词、标签、精度和计分规则，并记录新输出。
- 有基础模型和训练环境：可重新训练一个LoRA适配器；训练完成后需要实际测试，新训练结果不预先保证等于原成绩。
- 有ASR模型和录音：可通过现有单条音频入口进行转写与识别。本次没有新增整库音频测试入口。

这些录音没有用于梯度训练，但开发期间分析过该数据集上已观察到的错误。归档结果描述本次评测集上的表现，不应把公开复算理解为新增独立测试。已有模型预测的来源、复用记录和原始元数据均保留，未因论文精简而改写。

录音与匿名编号对应，例如`utt-0001.mp4`对应`utterances.utterance_id=utt-0001`。音频目录不属于SQLite，转写及预测记录也不等于音频文件本身。录音目录随上传继续更新，核对时应按匿名编号去重，检查`utt-0001`至`utt-0700`是否齐全；同一录音出现在不同目录时只算一条。公开音频是否齐全，不改变SQLite完整700条记录的复算。
